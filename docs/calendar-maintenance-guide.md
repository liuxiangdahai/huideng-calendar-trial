# 自动维护：怎么看、怎么处理

更新：2026-11-13。给项目负责人和接手维护的师兄；日常查看不需要下载文件，也不需要运行代码。

## 收藏这两个入口

| 想做什么 | 入口 |
|---|---|
| 查看最近一次检查和历史记录 | [资料自动维护](https://github.com/liuxiangdahai/huideng-calendar-trial/actions/workflows/calendar-source.yml) |
| 确认新资料是否已经上线 | [日历检查与发布](https://github.com/liuxiangdahai/huideng-calendar-trial/actions/workflows/calendar-trial.yml) |

打开第一个入口，点最上方的一次运行，在 **Summary（摘要）** 页向下找到“佛慧法语资料检查”。这里已有中文结论、资料确认范围、新增和修订数量，以及需要时的差异或发布链接。

**绿色只表示流程执行完成。** 没变化、生成了待核对资料、已交给发布流程，都可能显示绿色。请读中文结论；“已交给发布流程”也不等于手机已经同步。

## 每种结果要做什么

| 摘要或现象 | 含义 | 你的操作 |
|---|---|---|
| 原历内容没有变化 | 与现有资料一致，没有改写日历 | 无需处理 |
| 未发布月份 | 佛慧法语尚未提供该月份的确认资料 | 等后续检查，不补猜节日 |
| 有待核对变更、候选差异 | 原有日期或记录有修订，暂未自动发布 | 把本次运行链接交给维护者，按佛慧法语核对后发布 |
| 未知名称、日期不一致、缺页、删除或歧义 | 校验发现不能直接应用的资料 | 维护者处理名称映射或原始记录；反复点重试不会解决此类问题 |
| 网络超时、临时服务异常 | 本次没有取得完整资料，继续使用上一份有效数据 | 等来源恢复后重新运行一次 `check`；仍失败时交维护者排查 |
| 拒绝访问、验证码、页面结构变化 | 当前读取方式不能继续 | 停止反复重试，交维护者检查；不得把错误页或空页当成资料 |
| 已交给发布流程 | 候选检查通过，已请求既有发布流程 | 点摘要中的发布链接；该次发布成功且版本复核通过，才算上线 |
| 发布失败 | 新版未完成发布，不代表旧资料已失效 | 打开对应发布运行交维护者处理，不重复新建个人订阅 |
| 没有完整报告／维护记录写入失败 | 程序或权限环节没有完成 | 以运行页失败步骤为准；旧的“最新记录”不能代表这次成功 |
| 超过35天没有新检查 | 定时任务可能停用、延迟或漏跑 | 检查工作流是否启用，手动运行一次 `check`；仍不能运行再排查账号与权限 |

给维护者的信息只需：**运行链接＋看到的提示＋希望核对的日期**。不要发送个人订阅地址、管理链接或账号密钥。

## 需要时自己检查一次

1. 登录仓库所属的GitHub账号，打开[资料自动维护](https://github.com/liuxiangdahai/huideng-calendar-trial/actions/workflows/calendar-source.yml)。
2. 点 **Run workflow（运行工作流）**，分支保持 **main**。
3. 只想确认情况，选择 **check**；希望按现有保护规则检查并更新，选择 **maintain**。
4. 点确认运行，稍后刷新列表，打开新记录查看中文摘要。

`check`不改日历资料，也不发布，但会保存检查记录。`maintain`仍须通过所有校验；它不是“跳过错误强制更新”。如已有候选分支等待核对，先处理该分支，不反复创建或强推。

普通无变化检查通常数分钟完成；有新资料时会继续做完整程序、浏览器和发布检查，等待更久。点击运行不代表检查或更新已完成。

## 邮件通知：需要在你自己的账号里开启

目前程序保存GitHub运行摘要和仓库记录，**没有接入微信、短信或单独邮件服务**；也未替你改变个人通知偏好。

1. 打开[GitHub个人通知设置](https://github.com/settings/notifications)。
2. 找到 **System → Actions**，开启 **Email**；需要时也开启 **On GitHub**。
3. 如果只想收失败通知，可选 **Only notify for failed workflows**，然后点 **Save**。

如果还希望知道每次检查正常完成或出现绿色的“待核对”结果，先保留全部完成通知；只订阅失败通知不能覆盖所有待核对情形。通知也不会在“工作流根本没有运行”时自动报警，仍需看最近检查时间。

GitHub通知与触发账号有关：手动运行通知发送给发起者；定时通知与创建工作流、最后修改定时规则或重新启用工作流的账号有关。后续交接给另一位维护者，应重新确认收件账号。开启全部完成通知后，可手动运行一次 `check`，确认收信，再按需要改成仅失败。依据：[官方通知设置](https://docs.github.com/en/subscriptions-and-notifications/how-tos/managing-github-actions-notifications)、[通知接收规则](https://docs.github.com/en/actions/concepts/workflows-and-actions/notifications-for-workflow-runs)。
