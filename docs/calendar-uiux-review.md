# 慧灯藏历：本轮 UI/UX 审阅与建议

日期：2026-11-05。用户随后提供纹样参考并授权直接实施，包括本文件中的UI/UX改进。**本轮候选已落实每日日期附加行、订阅连接详情、文字/底色与边角装饰，正在按既定流程验收。** 下文保留问题与设计依据；发布状态和证据以执行计划为准。

审阅基线为源码0521057及已存截图：此前每日藏历组件在97778a2加入，参考 `docs/evidence/daily-ui-97778a2/mobile-selection.png`；此前订阅面板见 `docs/evidence/subscription-flow-0521057/`。本轮实施截图集中于 `docs/evidence/ornament-ui-20261105/`，旧截图只用于说明修改前的问题，不用于证明新版通过。

## 1. 每日藏历：独立行为，连贯呈现

当前结构在三项快捷方案之后，先解释第三方案的排除范围，再放两条分隔线、一个复选框、较长说明及单独展开帮助。手机上形成一整块，与上方的图标、字体和对齐不一致，容易被看成后来补入的第四种方案。它实际是附加内容，不是操作按钮，也不是第四个互斥方案。

**推荐：保留位置和独立复选行为，融入快捷方案区域底部的一行附加内容。**

- 可见标签：“加入每日藏历”；辅助状态：“仅显示”。
- 简短说明：“每天一条全天日期，不设置提醒。”
- 同行或紧邻的小文字入口：“显示示例”。展开才显示“藏历十月初一”“藏历九月初九（重日1）”“藏历闰二月初一”，以及手机日历每天会多一条全天日程的说明。
- 一条分隔线即可；标题和文字起点与上方方案内容对齐，沿用纸色背景。采用已有线条日历图标时保持尺寸一致；不再用新的彩色大卡片和徽章制造层级。
- 复选框放在清晰、可点击的整行内；视觉框可小，整个点击区域至少44px。保持键盘焦点和原生勾选语义，不把选择事件绑到帮助链接或嵌套按钮。
- 不优先做成即时生效的开关：现有订阅需要点“保存修改”才更新，复选框更能表达“选入此次订阅”。若采用开关外观，仍必须明确草稿与已保存的区别。

避免使用“必须选一个方案后才可加入”这样的交互或文案。用户可以只订阅每日藏历；不要用“同时加入”暗示它不能独立使用。切换三方案仍保留勾选；清空全部关闭；批量提醒不影响它。

不建议把它移入提醒弹窗、折叠到“高级设置”深处，或让用户再加第二份日历。它属于订阅内容，首次使用者应能发现。

## 2. 视觉方向

延续“暖纸上的藏历”：雪山横幅和慧灯标志形成品牌识别；内容区域像经过细致排版的历书，安静、有结构、便于查阅。

用户提供的参考图用于美术语言参考，不从图片里顺带新增天气、宜忌、会员或支付功能，也不把图中示例日期作为真实数据。慧灯标志沿用原图等比显示；不伪造藏文、重绘标志或用生成图片替代可点击的日历控件。

| 角色 | 方向 |
|---|---|
| 页面底色 | 暖纸色，统一明度；避免叠加多层偏黄渐变 |
| 日历和输入内容面 | 比底色更浅的近白纸色，拉开层次而非处处画深边框 |
| 正文 | 深墨色；功能文字15–16px为主，说明13–14px |
| 品牌/少量标题 | 衬线字，字号和字重明确；表单和长日程名用系统黑体 |
| 主要动作及选中状态 | 绛红；不要把帮助、普通小字、每个边框都涂成主色 |
| 导航/结构 | 深青少量使用；避免每层都加一条厚实深色标题栏 |
| 装饰 | 古金细线、少量祥云/结饰；限定于品牌与主要区域端部，不进入日期文字和触控区域 |

可从当前变量继续整理：底色`#f4eddf`、内容面`#fffaf0`、文字`#30251f`、绛红`#681e19`、深青`#173b40`、古金`#a47a3d`。这是角色约束，不要求每个模块都出现六种色。小号文字不用装饰金色代替可读的正文色；对比度以实际组合测量。

“高级感”的验收应看具体表现：同角色控件一致、间距有规律、长名称不挤压、装饰有集中位置、正常/选中/禁用/失败容易区分。不能仅靠多加纹样、圆角卡片、金色描边、阴影或一句“提升高级感”完成。

## 3. 优先级与可观察的改进

| 优先级 | 问题 | 改进方向 | 应看见的结果 |
|---|---|---|---|
| P1 | 每日藏历像独立补丁 | 按第1节做附加内容行 | 看得出它可独立勾选，且能与任一方案共存 |
| P1 | 选择区层次靠多段说明和线条分割 | 固定“快捷方案 → 附加日期 → 按分类调整”；压缩同义重复 | 不再多造一层标题和卡片，进入分类的滚动距离减少 |
| P1 | 订阅弹窗里连接状态占较大面积，主操作靠后 | 正常状态收成一句，检查时间/诊断折叠；添加操作紧接应用选择；错误在对应操作旁展开 | Google/Outlook先复制再打开一眼可见，Apple直接添加也清楚；失败仍保留备用入口 |
| P2 | 所有区域都争主色和金线 | 收拢颜色角色、统一线宽圆角和间距 | 首先看到当前内容与下一步按钮，再看到装饰 |
| P2 | 长日程名、仅显示和提醒状态拥挤 | 名称有足够换行宽度，提醒为安静的右侧/下方操作；单项铃铛、批量设置图标区分 | 五项同日日程可连续读完，提醒入口明确，不靠颜色猜状态 |
| P2 | 月历和详情重复标题，今天/选中混淆 | 当前月份为主标题，藏历月份为副标题；今天与选中分别表达，手机保留可读日程简称与下方全名 | 无须读图例才能找到今天、当前选择和活动名称 |
| P2 | 空选择时缺少温和的下一步 | 底栏说明“先选择修行日或每日藏历”，月历仍可查日期；不默认勾选 | 新用户知道为何不能提交，也不会误以为必须选荟供方案 |
| P3 | 图片或字体美化可能拖慢页面 | 复用已优化资产、字号与系统字体；清理重复样式，再考虑新图片 | 界面统一且不新增大体积资源或主线程负担 |

三方案保留统一的“名称、范围、提醒规则”结构，去掉同义重复，不为凑固定行数硬塞文案；也不把“当天08:00”写死在会保留用户自定义时间的方案卡上。第三方案的范围与静默规则必须看得见。

## 4. 手机与电脑

- 小于1024px保留“选择内容 / 日期预览”吸顶切换，分别恢复浏览位置；首次预览直接到月历。底部操作栏继续常驻，清空为低强调操作。
- 390×844下优先让三方案和每日日期容易找到；不要为把所有分类塞进首屏而缩字或缩点击区。
- 宽屏保持左侧选择、右侧预览；展开长分类时月历上下文应容易返回。短屏不强行吸顶造成遮挡。
- “仅每日藏历”底栏继续显示“每日藏历 · 仅显示”；与修行日组合时区分修行日项数、提醒项数和每日日期，不把约820条每日日期混入选择数量。
- 弹窗在手机键盘打开、横屏和电脑缩放时仍可滚动到保存/关闭。不要用截断、隐藏溢出掩盖布局错误。

## 5. 本轮设计验收

1. 提供320、390、585、768、1024、1440px检查；至少390/1440同状态对照。展示未选择、仅每日、全部修行日加每日、长名称、设置未保存及失败状态。
2. 验证每日默认关闭、只选每日可订阅、方案切换保留、清空关闭、批量提醒不影响、保存失败保留勾选。关闭/重开沿用同一订阅地址和原有版本逻辑。
3. 无横向溢出、重要操作被固定栏挡住、字体被裁切；主要触控区至少44px。普通文字4.5:1、必要边界/焦点3:1，颜色不作为唯一标识。
4. 搜索、恢复默认和撤销已按用户要求取消，本轮不要以套模板为由恢复。时区搜索仍需要保留。
5. 仅显示和每日日期无网页主动设置的提醒；不以点击、连接正常或导入成功宣称真机通知通过。
6. 不引入框架重写、不改变日期数据/接口/设置格式；任何超出本轮的优化单独解释影响。
7. 运行相关回归与既定发布检查；性能另测，旧CPU/冷启动失败不能改写为通过。交付可运行实现和截图，不只给设计形容词。

本轮按P1优先完成；保留现有雪山和标志，新增两张小型原创SVG。根据用户最新反馈，每日日期与方案共享暖纸底，不单独使用青灰色。正常连接状态显示一行；诊断信息可展开，失败自动展开。功能、视觉与发布验收记录见执行计划及同日期证据目录。
