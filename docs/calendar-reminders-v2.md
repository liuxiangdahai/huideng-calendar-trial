# 藏历订阅日历

入口仍是 `/calendar-reminders/`，保留现有 Hugo 网站与菜单。页面改为七类折叠列表、原称/别名搜索、单项选择、独立提醒面板、近期预览和长期订阅。主界面不再显示宣传区、开始日期、加入范围或资料读取日期。

视觉采用温润纸色、深朱红与古金细织锦边饰，荟供分类使用原创金刚杵线条图标。页面移除本地体验与尚未接通等开发说明；无法完成订阅时在实际操作后提供普通失败提示，并保留选择和文件导入。没有有效后台响应时，不生成订阅凭证或成功状态。

本轮完整可行性复核及官方依据见 [日历可行性复核](calendar-feasibility.md)。长期日期订阅、跨平台精准提醒和持续维护节日资料是三项需要分别验收的能力。

## 日期和节日

- 底层是藏历 PRO `0.2.0`，固定提交 `c29e60f8292473c038a1da7d5a4061a3c97026fa`，ESM 适配及 MIT 许可保存在 `static/calendar-reminders/vendor/zangli/`。支持 1951-01-08 至 2051-02-11。
- 佛慧法语原称与公布安排优先。现有 491 天与 PRO 逐日相符；此前的差异实际在节日规则，不是日期换算。
- 七类共 60 个可选项目，映射 62 种源标签、203 条公布记录。日环食/月偏食带不同时间注记的名称在选择目录合并，实际日程保留各次原文。搜索别名不改变显示标题。
- 分类数量：荟供日 2、佛菩萨殊胜日 12、上师纪念日 14、法会与修行月 16、藏历节庆 6、节气与天象 8、其他纪念日 2。神变月、萨嘎月、转法轮月与天降月放在修行月分类。
- 36 项明确固定规则可延伸至未来；24 项法会边界、节气、天象等只使用明确记录，不根据一年数据猜测以后安排。月度包含闰月、缺日前移、重日首次；年度不自动重复到闰月。
- 对已完整覆盖的来源区间，公布记录取代规则结果。事件永久标识不包含可变的公历日期、标题或提醒设置；非固定发生记录使用登记册中的永久 ID。

`data/calendar/fohui-dates.json` 为来源事实；`catalog.json` 为目录及明确规则；`published-record-ids.json` 为非固定记录登记册。公开资料只保留日期、短名称、来源链接和页面哈希，不分发原网页或长篇内容。

## 偏好与订阅

偏好版本 `2`：`{version:2, zone, events:{eventId:{mode,reminders}}}`。mode 为 `off/display/remind`。提醒支持当天/提前 1、2、7 天及最多两次具体时分。

新用户仅默认莲师荟供日当天 08:00 提醒。迁移 v1 时只迁移原十项的实际选择，新加条目保持关闭；删除原先的日期范围偏好。旧 v2 选择不因新版默认值改变。每项独立保存，分类统一设置由用户明确触发。

夏令时重复时刻取第一次，空缺时刻按跳过的时长顺延；例如温哥华的春季 02:30 顺延至 03:30。滚动订阅遇到未来夏令时转换时不会因此中断。

Hugo 负责页面，Cloudflare Worker + D1 负责订阅。匿名管理凭证与只读订阅地址分离。修改设置保留地址；日历客户端自行决定刷新频率。前端草稿、服务端已保存状态和手机实际同步状态分开显示。

订阅窗口自动滚动为过去 90 天至未来 24 个月。UID 稳定，变化递增 SEQUENCE，并保留创建/修改时间；取消条目保留 90 天撤销信息，随后清除内容、保留必要的序号防止重选倒退。接口及部署细节见 [订阅服务说明](calendar-service.md)。

## 开发与验证

需要 Node.js 24+。

```sh
npm ci
npm run build:calendar
npm test
npm run build:standalone
npm run test:browser
npm run dev:calendar
```

本地开发地址 `http://127.0.0.1:4173/calendar-reminders/`。同一服务器运行实际订阅逻辑，以本地 SQLite 持久存储，数据库保存在忽略的 `.calendar-preview/` 目录。它不创建外网可用的手机订阅。

浏览器回归启动独立服务并使用内存数据库；不会复用开发订阅或累计触发创建限额。CI 仅上传页面截图，不上传数据库、日志或订阅凭证。

单文件体验版输出到仓库外的 `藏历订阅日历-体验版.html`，同时刷新上一版文件便于已打开的浏览器标签重载。离线版可选择、预览和导出，不模拟订阅成功。正式页面通过同目录 `config.json` 的 `apiBaseUrl` 接入实际 HTTPS 服务；默认留空，避免发布假地址。

验证包含 PRO/source 日期、完整目录、跨时区、缺日重日闰月、未来规则、独立 ICS 解析、v1迁移、真实 SQLite 订阅生命周期、并发修改、撤销及浏览器操作。
