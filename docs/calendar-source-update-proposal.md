# 佛慧法语资料自动检测与订阅更新：讨论方案

日期：2026-11-04。状态：已审阅并提出方案，**未启用自动抓取、自动合并或新定时任务**。当前优先完成提醒真机证据和线上503排查，不绕过现有发布门槛。

## 当前事实

- PRO固定版本负责藏历换算；佛慧法语负责节日名称和明确安排，不自动升级日期引擎。
- `tools/calendar/import-fohui.mjs`从已保存的月份HTML导入。它并非联网检测器；现有发布工作流没有定时资料抓取。
- 仓库当前资料读取日期2026-10-20，实际确认到2027-05-06。这只是本项目快照，不能推断原站现在仍只发布到该日。
- 导入器要求连续至少365天、日期不重复；构建要求所有原始标签可归类、PRO日期一致、非固定日程有稳定记录编号。未知名称或不明改期会报错。
- 导入器当前整份重写输出，不能将一次局部下载、空页或失败页直接喂给生产更新。目录中的来源安排和记录编号也不能仅靠更新一个JSON完成同步。
- 本轮网页工具读取原站受到robots限制，未实时核对原站新增资料或站点对定时抓取的许可；实施前需检查允许的获取方式，必要时向站方获取数据接口/授权导出。不绕过访问限制。

## 推荐流程

沿已有GitHub Actions增加低频资料任务，建议每天一次；定时抓取不放进用户打开网页/日历取数请求，也不另起长驻服务器。不增加会员、数据库表、订阅地址或付费方案。私有仓库运行分钟和存档占用需纳入额度统计；定时任务可能延迟，不能承诺精确到分钟。

1. **获取候选资料**：只访问允许的公开月份范围，限并发、设置超时和有限重试；支持ETag/Last-Modified时使用条件请求。使用明确的程序标识，不抓无关网页。
2. **保留来源快照**：记URL、读取时间、内容摘要、覆盖范围。原始HTML只解析文本，不执行脚本；输出内容继续转义。一次下载失败不破坏原有已确认记录。
3. **生成差异**：分别列新增日程、名称变化、日期变化、删除、覆盖范围缩小和未知标签。没有实质变化时不生成发布，不反复改版本。
4. **运行校验**：连续日期、月末/跨年、缺日/重日/闰月、全部标签映射、跨夜天象去重、来源与PRO一致、稳定记录编号、已有选择兼容。记录改期必须沿用旧UID；不把旧日程改期误作删除+新建。
5. **初期提交资料更新PR**：自动获取和检查，维护者确认差异后沿现有验收→试用流水线发布。PR由受控工作流生成；不能假定GITHUB_TOKEN创建的PR/推送必然触发另一条workflow，须显式验证检查触发链与权限，严禁静默绕过检查。
6. **后期可收窄范围自动更新**：只有“已知项目、未来新发生记录、身份明确、无旧记录修改、校验全部通过”的低风险增量，才考虑自动合并发布。新节日、改名、改期、删除、明显范围回退、解析异常和重复身份均停在待核对。
7. **发布与客户端同步**：前后端共享新资料摘要，使快照失效；同条目UID不变、确有内容变化时SEQUENCE递增；原订阅地址不变。用户手机何时拉取由客户端决定，不能把服务端发布成功写成手机已同步。

资料任务只维护日程事实。用户勾选项目、逐项提醒和时区保持原样；新增目录项目默认关闭。已选择的现有项目，新一期明确记录可进入同一订阅。每日藏历继续由PRO生成、保持无提醒。

## 失败处理与验收门槛

| 场景 | 必须满足 |
|---|---|
| 原站超时/验证码/结构改变/无资料 | 检测失败或待确认；保留上一有效数据和在线订阅，不清空日程 |
| 页面200但缺天/缺月/空正文 | 不当成“节日被删除”，不发布 |
| 新标签或名称变化 | 给出可读差异，阻止自动合并，不能静默丢弃 |
| 改期与跨夜天象 | 明确关联稳定记录编号，同一事件不重复；不机械按某年藏历日期外推 |
| 同一份资料重复运行 | 结果幂等，不产生新UID/重复通知，不无故递增版本 |
| 资料更新 | 验收订阅体现新事实，选择/提醒/时区保持；旧地址继续可读 |
| 暂时撤回与恢复 | 处理撤销/重启的版本单调递增，回滚不删除用户设置 |
| 自动检查失败 | 仓库保留运行状态和报告，维护者有明确核对入口；不往用户日历塞故障提示 |

正式自动任务至少用“无变化、未来新增、改名、改期、删除、未知名称、缺页、重复天象、发布失败”九组资料夹具验证；再在隔离环境完成一次实际资料更新及回退演练。未验证不标为已部署。

## 日期称呼建议

当前实现保持以下区分，先不改动已发布的日期名称：

- 日程标题：`藏历九月初九（重日1）`、`藏历九月初九（重日2）`。
- 小月格：`初九`及`重日1`/`重日2`，不恢复含糊的单字“重”。
- 详情：解释为“此藏历日期出现两次，这是第一次/第二次”，与各自真实公历日对应。
- 闰月：`藏历闰二月初一`；“闰”写在月份前，不用“润”。
- 不采用“初九/闰初九”这一组合，以免与闰月混淆。此处是界面用语取舍，不声称所有历书都禁止“闰日”这个称呼。
- 节日名称保持佛慧法语原文；重日并不表示同一节日必须两天都庆祝或提醒，安排继续按明确来源及现有规则。
