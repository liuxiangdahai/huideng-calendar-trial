## 8. 直接订阅入口实现与验收（2026-10-25）

### 当前流程

1. 用户选择内容后点击“订阅到日历”。Apple设备首次推荐Apple日历，已保存的实际应用选择优先；Android不猜测日历品牌。
2. 选定应用后自动准备个人订阅，移除理解成本较高的“创建地址”步骤。仅浏览网页、选择方案不会创建远端订阅。等待期间显示进度，关闭面板后仍可从“我的订阅”返回。
3. 地址就绪后：Apple设备显示真实的“打开Apple日历订阅”链接；Google电脑显示官方添加页面入口；Google手机说明转到电脑；其他手机提供复制网址与一次性文件导入。全部保留复制备选。地址未准备好、草稿未保存、保存冲突或恢复管理链接期间不能跳转。
4. 用户在日历应用中确认添加，再回网页按需勾选“已看到日程／已检查提醒”。页面失焦、回到网页、下载或复制不代替确认。无需授权浏览器通知。

Apple使用从有效HTTPS只读地址生成的`webcal://`链接，不在异步请求后自动唤起；支持iPhone、iPad（包括桌面UA）及Mac的推荐入口。Google使用官方页面`https://calendar.google.com/calendar/u/0/r/settings/addbyurl`，不把管理凭证或订阅内容写进跳转查询参数。其他Android没有未核实的Intent或品牌私有协议。

### 失败、管理与帮助

- 添加步骤默认折叠，主要动作优先；Apple补充“没有打开？”中文帮助，识别微信/钉钉环境，说明在外部浏览器继续或手动添加；不提供虚构的强制打开Safari按钮。
- Mac用户获得Mac操作说明；Google手机用户明确收到电脑交接提示；其他手机继续按已核实的品牌能力展示帮助。文件导入明确“不持续更新”，帮助浏览不清空检查进度。
- 失败创建必须明确点击重试；换应用、重复打开面板不自动再建一份。剪贴板两种复制方式都失败时提供可选中的只读地址，不显示虚假的复制成功。
- 修复管理链接竞态：正在保存或停用A时收到B的管理链接，先结束已发出的写入，再使用B自己的凭证恢复；旧GET返回不能覆盖已恢复的B。管理凭证不会进入日历链接。
- 成功恢复、重新载入或停用后清除上一操作的错误；恢复期间按钮和提示统一显示“正在恢复订阅”，仍可打开“我的订阅”查看进度。
- 接口、设置格式、数据库表、日期引擎与固定订阅地址机制均未改变。
